One token at a time

Before attention heads, GPU kernels, or KV caches, there is one simple job to understand: given the text so far, assign a score to every possible next token.

Model under inspection: Qwen3-0.6B Reading time: 9 minutes

What does the model actually do?

A language model receives a sequence of token IDs. It runs those IDs through a stack of learned numerical transformations and produces one number for every token in its vocabulary. Those final numbers express which token should plausibly come next.

A chat response is not produced in one grand act. It is assembled by repeating one next-token prediction, appending the chosen token, and predicting again.

This repeated computation is inference: using already-trained parameters to calculate an output. Training discovers the parameters. Inference uses them.

The central object For this chapter, ignore the whole conversation. Hold onto one object: a list of scores for the next token. Everything before that list exists to compute it; everything after exists to choose from it.

The words we need

Transformer vocabulary becomes manageable when each term is attached to a concrete object.

token
An item from the model's fixed vocabulary. A token can be a word, part of a word, punctuation, whitespace, or a special control marker.
parameter
A learned number stored in the model file. Parameters are often arranged into matrices called weights. Qwen3-0.6B contains hundreds of millions of them.
activation
A temporary number computed while processing a particular input. Weights persist across requests; activations change with the prompt.
hidden state
The current vector representing a token inside the network. In Qwen3-0.6B, the main hidden state has 1,024 numbers per token.
transformer block
A repeated module with attention and an MLP. Attention lets token representations gather information from earlier positions; the MLP transforms each position independently.
logit
An unnormalized score for one vocabulary token. A larger logit means “more favored,” but it is not yet a probability.
sampling
The policy that turns candidate probabilities into the selected next token. Greedy decoding takes the largest; stochastic methods intentionally preserve some uncertainty.

Where an inference engine enters

The mathematical description says “multiply this vector by that weight matrix.” A useful engine must decide where those bytes live, which kernel performs the multiplication, how work is batched, and which intermediate values must survive for the next token.

First

Prefill

Process all prompt tokens, usually in parallel, and build the initial key/value cache. Our five-token example enters together.

Then, repeatedly

Decode

Process one newly selected token while reusing cached keys and values from earlier positions. This avoids recomputing the entire prefix.

This is the bridge to llama.cpp. The model defines the operations and learned weights. The engine schedules and executes those operations efficiently on your hardware.

Carry this forward

Generation is a loop around next-token prediction. One pass turns token IDs into logits; a sampler chooses one token; the engine appends it and runs the loop again. Next, we will slow down the first two steps and inspect exactly how Qwen turns text into 1,024-number vectors.
